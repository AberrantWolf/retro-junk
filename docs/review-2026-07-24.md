# 0.4.0 whole-program review — 2026-07-24

This review followed the archive/playable Library integration pass. It focused
on authority boundaries, multi-disc behavior, UI responsiveness, network I/O,
platform identity, verification claims, and duplicated GUI/CLI behavior.

## Corrected during the review

- Library archive bindings now recover from catalog-backed analysis even when
  a playable CHD or M3U cannot expose raw DAT hashes. Ambiguous DAT names are
  deliberately not projected.
- Archived-only work is grouped by release. One action verifies and builds all
  missing discs, then creates an M3U only for a complete multi-disc set.
  When several physical copies exist, planning selects the best complete
  copy instead of mixing discs from different owned copies.
- Library availability distinguishes complete archives from incomplete
  archive links. Completeness uses the same release-level calculation as the
  Collection view: one physical copy must contain every catalog-expected disc,
  and every disc must have current complete catalog verification.
- M3U playable format is derived from its disc images. An all-CHD set satisfies
  a CHD policy; the playlist filename is not treated as the content format.
- “Verify & make playable” can create complete catalog evidence for Redumper
  masters and normalized single-file cartridge masters. Redumper staging now
  reports copied bytes and reuses the prepared local split for the immediately
  following CHD build instead of reading the archive across the LAN twice.
- Library exposes “Verify archive” even when an acceptable playable copy
  already exists, so catalog completeness never depends on starting a
  redundant conversion.
- Playable builds are idempotent after a partial release failure. A retry
  reuses already-present, evidenced outputs.
- Empty equivalent aliases such as `ps1` beside populated `psx` are removed
  safely. Regional hardware identities remain distinct for NES/Famicom,
  SNES/Super Famicom, Genesis/Mega Drive, Sega CD/Mega CD, Mark III/Master
  System, PC Engine/TurboGrafx-16, and the existing Saturn regional convention.
- CLI platform-default lookup now accepts canonical aliases, matching the
  archive projection and GUI.
- Import choices now include region, revision, variant, disc number, DAT
  source, and release ID, so genuinely duplicate-content releases no longer
  render as indistinguishable choices.
- Archive/profile edits no longer run archive scans on the UI thread.
- Fresh database initialization is serialized between the Library store's
  reader and writer workers, removing a schema-migration race found by the
  shutdown/reopen test.
- Settings write failures are surfaced instead of silently discarded.
- Archival releases are now first-class rows in the ordinary Library table.
  Catalog-bound playable files collapse into that logical release; genuinely
  unbound files remain separate “Playable only” rows. Region, completeness,
  preferred-format state, playable paths, and release-level actions are shown
  in the normal Details panel.
- A completed playable build now forces a content rescan of its existing
  console folder before archive bindings are reconciled. Folder discovery is
  no longer mistaken for a content refresh.
- Playable outputs now use the same DAT-canonical filename stems and
  multi-disc base-name derivation as Auto Rename. Slug naming remains only as
  the fallback for catalog-unbound archives.
- Collection summaries and selected-release details are loaded off the render
  thread and retained as an in-memory projection. Its virtualized table no
  longer executes aggregate SQL on every scroll frame.
- Ordinary playable rows no longer become highlighted merely because both
  their row and the current focus have no archive ID. Archive and playable
  focus now compare only concrete identities.
- A generated playable output is bound back to its archive release by the
  exact path recorded in build evidence. CHD no longer has to reproduce raw
  track hashes (or win a second serial lookup) to avoid appearing as a
  duplicate “Playable only” row.
- Logical archive rows now carry the concrete playable library entries they
  subsume. Details names every grouped CHD/M3U/ROM, shows its real format, and
  exposes the same scrape, hash, rescan, and rename actions used by standalone
  playable rows where those actions preserve archive evidence.
- Layout-mutating standalone actions (ordinary rename, CUE repair, ad-hoc CHD
  compression, entry tags/region overrides) are withheld from archive-derived
  rows. Those paths are owned by immutable build evidence; silently moving or
  rewriting them would make the archive projection stale.
- Release-level artwork already stored in the archive is projected into the
  Library status badge and Details panel instead of being stranded in the
  Collection hierarchy.
- Library pagination now operates on logical rows after archive/playable
  collapse. Hidden backing entries no longer consume page slots, and archive
  releases are not repeated on every page.

## Remaining work

### High priority

1. **Unify the CLI and GUI playable-build orchestration.**
   `retro-junk-gui` now uses the shared release-aware builder, but
   `retro-junk-cli/src/commands/archive.rs` still contains an older,
   carrier-oriented CHD pipeline and separate catalog/Redumper verification
   implementations. Its playlist projection knows only the carriers already
   present in manifests, not the catalog's expected disc count. Moving CLI
   commands onto the shared `retro-junk-lib::playable_build` release plan will
   prevent the two interfaces from drifting and will give CLI builds the same
   all-discs-before-M3U guarantee.

2. **Promote regional console identity into the core platform model.**
   Regional folder preservation currently sits above `Platform`, whose enum
   does not include PC Engine/TurboGrafx-16 at all and models several regional
   systems as aliases. The scan layer now avoids destructive collapsing, but
   unsupported systems cannot get a Library analyzer or preferred-format UI.
   A first-class physical-platform/catalog-platform mapping should replace
   string conventions spread across archive import, scanning, and projection.

3. **Finish archive-first release artwork acquisition.**
   The Library now displays release artwork that is already stored beneath the
   authoritative archive and lets an archived row with a grouped playable file
   use the ordinary scraper. A release that is still archive-only cannot yet
   launch a targeted scrape, and ordinary playable scraping still writes the
   frontend asset tree without automatically ingesting those downloads as
   release-level archive files. Add one release-oriented scrape job that uses
   catalog media for identification, writes each original download once to the
   archive with source URL/provenance, and then projects or links the selected
   frontend layout from that source.

### Medium priority

4. **Report streaming progress for normalized single-file verification.**
   Redumper copy and CHD conversion now report real byte progress. Cartridge
   verification still calls the shared hasher without a progress callback, so
   a very large single-file master reports only its phase and final result.
   Extend the hash reader API rather than adding another hashing loop.

5. **Recover or prune interrupted prepared-Redumper scratch caches.**
   Successful builds remove `workspace/prepared-redumper/<manifest-sha256>`.
   An interrupted run intentionally leaves the cache reusable, but there is no
   age/space policy or startup recovery UI. Add an indexed scratch-cache
   inventory and a safe “clear unused workspace” action.

6. **Move remaining filesystem probes out of GUI message handling.**
   Alias cleanup performs shallow `read_dir` probes when folder scanning
   completes. It reads no file contents and is bounded by console count, but a
   stalled mount can still delay one UI frame. Include populated/empty status
   in the background folder-scan result instead.

7. **Improve duplicate-content catalog decisions.** The import UI now exposes
   enough fields to distinguish candidates, but releases that intentionally
   share identical media still require a manual choice. Model “same dumped
   media, multiple packaging releases” explicitly so the physical copy can
   record packaging identity without implying that disc hashes distinguish it.

### Documentation and maintenance

8. **Reconcile `TODO.md` with the shipped archive architecture.** Its “Raw
   Redumper Archival + Dual Representation” section is still written as a
   preimplementation design with unchecked items and now-obsolete proposed
   paths. Convert it to follow-up tasks and point to
   `docs/archive-architecture.md`.

9. **Consolidate platform-equivalence helpers.** Equivalent parsing currently
    exists in the database projection, GUI policy code, GUI scanner, archive
    import, and CLI. Once physical regional identity is modeled, expose one
    typed mapping API and delete the local string helpers.

10. **Add end-to-end fixtures for a four-disc release.** Unit coverage now
    proves playlist gating and release grouping primitives. A fixture should
    ingest four catalog-bound raw discs, leave one unverified, assert
    incomplete status and a disabled build, verify it, build all CHDs, and
    assert one Library row plus one four-entry M3U.

11. **Make the workspace's pedantic Clippy policy actionable.**
    `cargo clippy --workspace --all-targets -- -D warnings` currently promotes
    a broad pre-existing set of style and enum-size warnings in
    `retro-junk-gui` to errors. Either address that baseline as a focused
    cleanup or configure explicit, documented allowances; otherwise the
    command cannot serve as a regression gate. Functional workspace tests and
    normal compilation remain the current reliable gates.

## Review notes

- Validation completed with `cargo check --workspace`,
  `cargo test --workspace`, the archive projection integration tests, all GUI
  unit/UI tests, and the shared playable-build tests. The final release-action
  query changes were rerun through their targeted database and GUI suites.
- No operation deletes preservation masters. Source consumption remains an
  explicit import option guarded by post-copy rehashing.
- Archive completeness is a catalog claim, not an integrity claim. Byte
  integrity alone never marks a release complete.
- A playable representation may legitimately exist while its archive is
  incomplete; the Library now names that state rather than flattening it into
  “Archived + playable.”
